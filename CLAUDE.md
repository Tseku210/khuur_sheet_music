# khuur_sheet_music

Flutter package that renders sheet music on a `Canvas` and plays it back over MIDI. [Khuur](https://github.com/Tseku210/khuur_app) is the first app that uses it.

## Commands

```bash
flutter pub get          # also resolves example/
flutter analyze          # library, tests, and example; must report no issues
flutter test             # the view's, the painter's and the player's tests in test/
cd packages/khuur_score_model && dart test   # score model tests (not run by flutter test)
cd packages/khuur_score_model && mkdir -p build && dart compile exe benchmark/playback_benchmark.dart -o build/playback_benchmark && build/playback_benchmark   # playback compile scaling check, compiled; exits 1 when a longer score costs out of step
cd packages/khuur_score_layout && dart test  # layout engine tests (not run by flutter test)
cd packages/khuur_score_layout && mkdir -p build && dart compile exe benchmark/layout_benchmark.dart -o build/layout_benchmark && build/layout_benchmark   # layout cost benchmark, compiled; exits 1 when over budget
cd packages/khuur_score_model && mkdir -p build && dart compile exe benchmark/erase_benchmark.dart -o build/erase_benchmark && build/erase_benchmark   # erase cost under glissandi that name their notes, compiled; exits 1 when they cost out of step with unnamed ones
cd packages/khuur_score_model && mkdir -p build && dart compile exe benchmark/erase_growth_benchmark.dart -o build/erase_growth_benchmark && build/erase_growth_benchmark   # erase cost against score length, compiled; exits 1 when either erase grows past its bound
cd packages/khuur_score_layout && dart run tool/generate_bravura.dart   # rewrites lib/src/bravura.g.dart from tool/bravura_metadata.json
cd example && flutter test   # the example app's tests (not run by the root's flutter test)
flutter test verification/score_player/orders_test.dart   # every order of up to 7 steps on ScorePlayer, checked against its promises (not run by flutter test)
cd example && flutter run            # the example app, Android or iOS
```

## Layout

- `lib/khuur_sheet_music.dart` is the public export list. It exports all of `khuur_score_model`, the `khuur_score_layout` types it names, and the shell in `lib/src/`. Anything not exported there is internal.
- `packages/khuur_score_model/` is the pure-Dart score model, a pub workspace member. Its design and the deviations accepted while implementing it are in `docs/design/score-model/RATIONALE.md`, which is kept on the maintainer's machine and is not in git.
- `packages/khuur_score_layout/` is the pure-Dart layout engine, a pub workspace member. Its design and the deviations accepted in each unit are in `docs/design/layout/RATIONALE.md`, also kept locally. `SheetLayout` is its entry point. Its glyph table `lib/src/bravura.g.dart` is generated by `dart run tool/generate_bravura.dart` from `tool/bravura_metadata.json`. `benchmark/layout_benchmark.dart` is the layout cost gate, and every change to the engine reruns it.
- `lib/src/sheet_view.dart` holds `SheetView` and `SheetController`. The view shows a `Score` as a scrolling list of system tiles over `SheetLayout`, drawn by the one painter in `lib/src/painting.dart`, measured by `lib/src/paragraph_measurer.dart` and coloured by `lib/src/sheet_palette.dart`. The view's own scrolls (`ensureVisible`, a moved cursor, playback) run in `_OwnScroller`, in the part file `lib/src/own_scroller.dart`. The painter draws glyphs as text in `fonts/Bravura.otf` (licence in `fonts/OFL.txt`).
- `lib/src/score_player.dart` holds `ScorePlayer`. It plays a `khuur_score_model` playback script from one script clock through the `MidiOutput` seam of `lib/src/midi_output.dart`. Its `SynthOutput` plays through FluidSynth from `khuur_synth` (Android and iOS only), one synth for each output, and loads the `SoundFont`s that the app passes in, which are `khuur_synth`'s own.
- `test/mock/` holds hand-written fakes, `fake_midi_output.dart` and `fake_wall_time.dart`. Tests do not use a mocking package. `test/support/` holds the helpers that draw and write pictures.
- `example/lib/main.dart` is the example app, one page over `SheetView` and `ScorePlayer`. `example/lib/demo_score.dart` builds its tune. `example/test/` tests both and imports the root's `test/mock/` and `test/support/` by relative path.

## Conventions

- Lints come from `pedantic_mono`. Keep `flutter analyze` clean.
- Asset paths that code loads at runtime must use the `packages/khuur_sheet_music/` prefix. A bare `fonts/...` or `assets/...` path only resolves inside this package, not in a consuming app.
- The package bundles no SoundFont, because Flutter ships every package asset to every consuming app. The example app bundles `example/assets/soundfonts/piano.sf2`, FreePats' CC0 Upright Piano KW (full, 57 MB). Git does not track it. `cd example && dart run tool/fetch_soundfont.dart` downloads it and checks its SHA-256.
- Commit messages use Conventional Commits: `type(scope): description`.
- A release updates the site's docs in `site/src/content/docs/` in the same pull request as the version raise, as step 2 of "How a release goes out" in `CONTRIBUTING.md` says. `.github/scripts/check_release_docs.sh` runs in CI and fails when a CHANGELOG or the tutorial names a version other than the pubspec's.
- The library is open source and stays general. Khuur is its first consumer, not its target, so nothing Khuur-specific goes in `lib/` or `packages/`. Instruments, marks and examples are general, and Khuur's designs guide scope without being requirements.
